# Конспект по DHCP

## Основы

DHCP это протокол который автоматически раздает IP-адреса. Расшифровывается Dynamic Host Configuration Protocol.

Каждому компу и роутеру в сети нужен IP-адрес. Если делать это руками то админ должен каждому устройству вписывать айпи, маску, шлюз, днс, доменное имя и еще кучу всего. И помнить какие адреса заняты а какие свободны. Это утомительно даже в маленькой сети.

DHCP все делает сам. И следит чтобы адреса не дублировались потому что управление централизованное.

## Предки DHCP

Сначала был RARP. Ему больше 30 лет. Работал так: клиент орал на всю сеть, сервер слышал, смотрел в базе по MAC-адресу какой IP положен и отправлял ответ.

Минусы RARP:
- сервер надо ставить в каждом сегменте сети
- MAC-адреса регистрировать вручную
- доп информацию клиенту передать нельзя

Потом сделали BOOTP. Для бездисковых станций которым нужен был не только IP но и адрес TFTP-сервера и имя файла загрузки. Тут появился relay - посредники которые пересылали запросы главному серверу. Один сервер мог обслуживать несколько сетей. Но таблицы все равно настраивались руками и размер доп информации был ограничен.

Потом сделали DHCP. Он совместим с BOOTP, то есть DHCP-сервер может обслуживать старых BOOTP-клиентов, но не наоборот.

## Режимы работы

Работает по модели клиент-сервер. Комп включается, DHCP-клиент шлет в сеть запрос, сервер отвечает и дает адрес плюс другие параметры.

Режимов три:

Ручной режим. Админ сам прописывает какой IP какому MAC-адресу соответствует. Сервер всегда выдает конкретному клиенту один и тот же адрес.

Автоматическое назначение статических адресов. Сервер сам выбирает клиенту IP из пула но выдает навсегда. Адрес закрепляется за клиентом на постоянку, просто выбирается автоматически.

Динамическое распределение. Сервер выдает адрес на время, это срок аренды. Комп уходит из подсети - адрес освобождается. Подключился к другой - получил новый. Ни юзер ни админ не вмешиваются.

## Пример с мобильными сотрудниками

Организация где 500 сотрудников но большинство в разъездах. Если каждому выдать постоянный IP то надо получить адреса двух сетей класса C и оборудовать помещение на 500 мест. Большая часть будет простаивать.

Если использовать динамику то можно взять всего 64 адреса и 64 рабочих места. Потому что в офисе одновременно не больше 50 человек. Пришел сотрудник, подключил ноут, DHCP-клиент запросил параметры, получил автоматически и работает. Ушел - адрес освободился.

То есть для 500 мобильных сотрудников хватает 64 IP-адресов и 64 рабочих мест.

## Алгоритм динамического назначения

Админ настраивает две вещи:
- пул адресов которые можно раздавать
- срок аренды

Срок аренды зависит от использования. Учебный класс куда студенты приходят на пару часов - срок аренды равен длительности лабораторной. Корпоративная сеть где люди работают постоянно - срок может быть несколько дней или недель.

DHCP-сервер должен быть в одной подсети с клиентами потому что клиенты шлют широковещательные запросы. Если сервера в подсети нет то ставится связной DHCP-агент. Это прога которая работает посредником. Пересылает запросы от клиентов из одной сети серверу в другой сети. Так один сервер обслуживает несколько сетей.

## Обмен сообщениями по шагам

1. Комп включается, DHCP-клиент шлет широковещательное сообщение DHCP-поиска. IP-пакет с адресом назначения из одних единиц, для всех узлов сети.

2. DHCP-серверы получают сообщение. Если серверов нет то получает связной агент и пересылает серверу в другой сети, адрес которого знает заранее.

3. Все серверы которые получили поиск шлют клиенту свои предложения. В каждом IP-адрес и другая конфигурационная инфа. Сервер из другой сети шлет ответ через агента.

4. Клиент собирает предложения. Обычно выбирает первое и шлет широковещательный DHCP-запрос. Указывает какой сервер выбрал и какие параметры принимает.

5. Все серверы получают запрос но только выбранный шлет положительную квитанцию. Остальные аннулируют предложения и возвращают адреса в пулы.

6. Клиент получает квитанцию и переходит в рабочее состояние.

Потом комп периодически пытается обновить аренду у того же сервера. Задолго до истечения срока. Если сервер не отвечает или отказывает, клиент пробует еще несколько раз, потом обращается к другому серверу. Если и тот отказывает, клиент теряет параметры и переходит в режим автономной работы.

## Проблемы динамических адресов

Первая проблема - сложно с DNS. Система DNS должна поддерживать таблицы соответствия имен и IP-адресов а адреса меняются каждые два часа. Поэтому для серверов к которым часто обращаются по имени назначают статические адреса. Динамические оставляют только для клиентских компов. Но если серверов много то ручное конфигурирование становится обременительным. Поэтому сделали динамическую версию DNS где базы DHCP и DNS согласуются.

Вторая проблема - сложно удаленно управлять и мониторить устройства если их идентификатор постоянно меняется. Со статическими адресами админам проще, они знают IP устройства и могут подключиться.

Обычно статические адреса дают:
- маршрутизаторам
- серверам
- принтерам
- другим сетевым устройствам которые вряд ли поменяют местоположение

И еще для безопасности. Многие устройства фильтруют пакеты по IP-адресам. Если адреса динамические то фильтрация усложняется. Поэтому для интерфейсов которые участвуют в системах мониторинга и безопасности тоже лучше статические адреса.
